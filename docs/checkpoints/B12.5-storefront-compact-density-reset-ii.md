# B12.5 · Storefront Compact Density Reset II

## Baseline

- Repository: `LuisHdezE/WebBlueprint`
- Base: `main@f21a8f66a335c9137d3a8942f4f1e737d8df750e`
- Branch: `fix/storefront-compact-density-ii`
- Trigger: visual review after B12

## Problem observed

The Storefront was functionally consistent but still consumed too much vertical space for a commercial catalog/admin-adjacent experience.

The screenshot review showed:

- H1 scale still visually dominant
- excessive vertical whitespace between intro, empty states and content
- cards and summaries using generous dashboard-like padding
- secondary labels/buttons occupying more height than needed
- shell chrome slightly taller than necessary
- content density below the intended compact ecommerce reference

## Goal

Reduce the perceived Storefront scale by roughly 30–35% in the areas that create vertical bulk while preserving readability, responsive behavior and the existing four-product desktop grid.

This is a density correction, not a redesign.

## Shared typography rule

`StorefrontPageIntro` now uses:

- H1: `text-2xl` with no larger desktop breakpoint
- eyebrow: 9px
- description: `text-xs` / compact line-height
- tighter vertical margins

This replaces the previous `text-3xl sm:text-4xl` H1 scale.

`StorefrontSectionIntro` is also reduced.

## Shell density

The Storefront shell is tightened through:

- smaller logo block
- shorter search field
- smaller utility/navigation controls
- reduced header spacing
- reduced footer spacing
- smaller floating WhatsApp action

The Storefront remains visually distinct from the Blueprint admin shell.

## Page density

The following views receive tighter paddings, gaps, radii and heading scales:

- Home
- Product listing
- Product detail
- Catalog route variants
- Cart
- Checkout
- Customer identity
- Shipping
- Favorites
- Contact
- Warranty / returns

Typical changes:

- `py-5 / lg:py-6` → approximately `py-3 / lg:py-4`
- `gap-5` → `gap-3`
- `p-5 / p-4` → mostly `p-3`
- `rounded-2xl` → `rounded-xl`
- secondary `text-lg / text-xl / text-2xl` scales reduced one step

## Intentionally preserved

The shared product-card geometry is **not** globally shrunk by 35%.

Reason:

- B7.7 intentionally established portrait-oriented cards
- desktop still needs four products per row
- product photography must remain commercially useful

The density reset therefore focuses on page chrome, headings, surfaces, summaries and spacing instead of making product imagery too small.

## QA guardrails

Architecture QA now rejects oversized Storefront page typography:

- no `text-3xl`
- no `text-4xl`
- no `text-5xl`
- no `text-6xl`
- shared page intro must contain `text-2xl`
- old `sm:text-4xl` breakpoint is forbidden

Browser QA tightens the effective desktop H1 limit to **26px** for:

- product listing
- cart
- checkout

Existing overflow, responsive, four-column and portrait-card checks remain active.

## Explicitly excluded

- no functional search/filter changes
- no backend work
- no provider/data contract changes
- no cart/checkout behavior changes
- no product-card redesign
- no new routes
