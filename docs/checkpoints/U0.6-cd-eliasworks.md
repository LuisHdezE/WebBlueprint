# U0.6 · CD → EliasWorks

Estado: **CERRADO · PRODUCCIÓN ACEPTADA**  
Baseline de producción: `main@854d3761c4625722e0ac91c1a45398aee37674bf`

## Objetivo

Publicar automáticamente las revisiones aceptadas de `main` de WebBlueprint en su propio subdominio independiente dentro de EliasWorks.

## Arquitectura canónica de producción

- URL pública: `https://webblueprint.eliasworks.uy`;
- raíz de la aplicación en el navegador: `/`;
- destino físico por FTP: `public_html/webblueprint/`;
- la raíz `https://eliasworks.uy` continúa siendo el portafolio Laravel independiente y nunca es sobrescrita;
- Render permanece como destino no canónico.

## Entregado

- CI conserva el `dist/` exacto validado de cada ejecución exitosa de `main` como artefacto `web-production`;
- CD se dispara únicamente después de un `push` exitoso de `main` que haya pasado CI;
- el job de despliegue descarga ese mismo artefacto, sin recompilar un segundo bundle;
- el guard de producción exige `index.html`, `.htaccess`, referencias raíz `/assets/...` y rechaza assets servidos bajo `/webblueprint/`;
- FTP escribe únicamente en `public_html/webblueprint/`;
- el smoke postdespliegue valida `/`, `/apps`, `/docs`, `/components` y `/demo/pet-shop/dashboard`;
- ADR-0005 fija la decisión de despliegue mediante subdominio independiente.

## Evidencia de producción

- PR #7 fue mergeada a `main` como `854d3761c4625722e0ac91c1a45398aee37674bf`;
- CI #74 pasó sobre ese merge commit exacto;
- el artefacto `web-production` se creó correctamente desde el build aceptado de `main`;
- el workflow `Deploy WebBlueprint to EliasWorks`, ejecución #1, consumió ese mismo artefacto;
- el primer intento de despliegue detectó que faltaba el secret `FTP_PASSWORD` del repositorio y se detuvo antes de publicar;
- tras configurar el secret, la publicación por FTP finalizó correctamente y creó el primer estado de despliegue en `public_html/webblueprint/`;
- el primer smoke HTTP detectó que faltaba el mapeo DNS/subdominio, sin requerir cambios en el código de la aplicación;
- después de crear `webblueprint.eliasworks.uy` con document root `public_html/webblueprint` y habilitar AutoSSL, se reejecutó el workflow de despliegue;
- el intento final terminó con todos los pasos en `SUCCESS`, incluida la validación del artefacto de producción, sincronización FTP y smoke de deep links sobre el subdominio canónico.

## Contrato de entrega

`push a main → CI de calidad/build → artefacto web-production validado → FTP → subdominio canónico → smoke HTTP/deep links de producción`

U0.6 queda cerrada. Las futuras revisiones aceptadas de `main` seguirán automáticamente este camino de entrega a producción.
