# A2.1 — Admin Master Data CRUD Mock

## Scope

Extends the Admin Master Data views from A2 with explicit demo CRUD interactions.

This increment keeps the experience inside the Backoffice/Admin shell and does not move into Inventory, Ecommerce or Storefront migration yet.

## Included views

- `/admin/master-data/brands`
- `/admin/master-data/device-models`
- `/admin/master-data/categories`

## Added interactions

Each view now supports demo-only actions:

- create;
- edit;
- activate / deactivate;
- delete.

The interaction model is intentionally in-memory only.

## Persistence boundary

QA status: PASS — CI, Automated QA, Browser QA, export smoke and deploy smoke must pass on the final PR HEAD before merge approval is requested.

The CRUD behavior is not persisted to backend, localStorage or any external storage.

The views display an explicit note stating that changes are kept in memory and reset on page reload.

## Validation rules

- name is required;
- slug is required;
- slug must be unique inside the edited collection;
- device model must reference a brand;
- category cannot be its own parent.

## Reused primitives

- `PageShell`
- `DataTable`
- `StatusBadge`
- `TextField`
- `TextAreaField`
- `SelectField`

No new persistence abstraction was introduced.

## Browser QA

Browser QA now validates, for brands, device models and categories:

- route deep link;
- table render;
- create action;
- edit action;
- deactivate action;
- delete action;
- search;
- reset;
- desktop screenshot;
- mobile screenshot;
- no horizontal overflow.

## Explicitly not included

This PR does not migrate Inventory Intake yet.

This PR does not create a backend, database, API, localStorage or fake persistence.

This PR does not change Storefront.

This PR does not change Ecommerce.
