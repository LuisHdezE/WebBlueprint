## Goal

Turn the authenticated Composer from a descriptive shell into a usable application-configuration workflow.

## Delivered flow

`Application → Branding → Preset → Features → Pages → Navigation → Review`

The Composer now owns one persistent project configuration and derives the manifest from that same state.

Implemented:

- editable application name, slug and description;
- logo URL and accent-color branding;
- Pet Shop as the first registry-backed preset;
- presets seed features, pages and shell without overwriting project identity or branding;
- blank-project mode;
- manual feature selection from the registry-derived Composer catalog;
- manual page selection from the registry-derived page catalog;
- governed left-menu variant selection;
- live navigation preview;
- persistent browser draft through local storage;
- deterministic `webblueprint.json`-shaped manifest preview;
- validation of application identity and accent color;
- direct `webblueprint.json` download when configuration is valid;
- unit coverage for stable IDs, preset behavior, validation and manifest generation.

## Responsive review

The Composer remains mobile-first:

- step navigation reduces from seven columns to compact multi-row layouts;
- forms, branding preview and selection grids stack before wider breakpoints;
- navigation and manifest review use responsive stacked layouts before desktop splits;
- the project-state sidebar becomes a normal document-flow section below the wizard until `xl`;
- wide manifest content is internally scrollable rather than widening the page;
- the shared `WorkspaceShell` / `LeftAppShell` continues to provide the mobile navigation drawer.

No separate Composer shell was introduced.
