# B12.6 · Storefront Ultra-Compact Cart Layout

## Baseline

- Repository: `LuisHdezE/WebBlueprint`
- Base: `main@312a5de7eddca882010dbe1a915129449d23b976`
- Branch: `fix/storefront-ultra-compact-cart`
- Trigger: visual comparison against a very dense Temu-style cart reference

## Goal

Make the Storefront cart feel like a practical ecommerce cart instead of a large marketing/dashboard composition.

The target is a dense utility layout with small typography, compact rows and a narrow order summary.

## Visual direction

The reference pattern uses:

- breadcrumb first
- minimal heading treatment
- compact informational strip
- line-item rows instead of large cards
- small square product thumbnails
- 9–12px typography for most metadata
- compact quantity control
- price aligned at the right
- narrow order summary
- almost no decorative card framing
- white content background

B12.6 adopts that density while preserving the existing Storefront theme tokens and responsive behavior.

## Cart line layout

Each cart line is now a flat row composed of:

- provider-driven product image reused from `productListing.products`
- badge
- product title
- subtitle
- compatibility
- stock
- compact disabled quantity control
- unit price
- line total

Desktop row structure:

`thumbnail | product details | quantity | price`

Mobile collapses naturally to the existing responsive grid.

## Typography

Key scale:

- H1: 18px
- product title: 12px
- line total: 12px
- metadata: 9–10px
- summary title: 12px
- total: 18px

This is intentionally denser than the general B12.5 Storefront scale.

## Empty state

The previous implementation displayed the reusable empty state even while demo cart lines were visible.

B12.6 corrects that:

- empty state renders only when `cart.lines.length === 0`
- demo line view does not simultaneously display an empty-cart panel

## Summary

The right summary column is simplified:

- border-left separation instead of a large card
- no shadow
- small 10px labels
- 18px total
- compact checkout controls

## Data / architecture

No new cart data source is introduced.

Product thumbnails are resolved from the existing Storefront listing through:

`provider.getProductListingView()`

and matched by product href.

This avoids duplicating product image URLs inside cart JSON.

## Explicitly unchanged

- no cart persistence
- no quantity mutation
- no add/remove item behavior
- no inventory reservation
- no backend
- no checkout activation
- no localStorage
- no sessionStorage
