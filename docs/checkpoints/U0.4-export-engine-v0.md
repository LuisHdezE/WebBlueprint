# U0.4 · Export Engine v0

Status: **READY FOR REVIEW**  
Base: `main@d1146ca6537997211e686dabf76b56850637114a`

## Goal

Prove that a valid Composer manifest can become a standalone React project rather than remaining only configuration data.

## Delivered

`Composer manifest → generated project files → deterministic ZIP → unzip → npm ci → npm run build`

The v0 export now:

- creates a deterministic React/Vite project from the Composer manifest;
- carries application identity, branding, selected features/pages and governed navigation into the generated app;
- includes `webblueprint.json`, `package.json`, `package-lock.json`, source files, Vite config and README;
- derives npm dependency metadata from the governed WebBlueprint toolchain;
- creates a browser-downloadable ZIP without adding a ZIP runtime dependency;
- exposes ZIP download only inside the authenticated Composer surface;
- keeps public routes free of export controls;
- validates deterministic project generation, lockfile alignment and ZIP output with unit tests.

## Runtime gate

CI #64 proves the actual archive path:

1. generate the ZIP;
2. extract that ZIP;
3. run `npm ci` inside the extracted project;
4. run `npm run build` inside the extracted project;
5. verify `dist/index.html` and `webblueprint.json` exist.

Result: **PASS**.

## Boundary

U0.4 proves a deterministic buildable React export. Broader page/component-library maturity remains outside this stage and continues incrementally in later roadmap work.
