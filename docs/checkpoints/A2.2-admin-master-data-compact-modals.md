# A2.2 — Admin Master Data Compact Modal CRUD

## Scope

Refines the Admin Master Data CRUD mock experience introduced in A2.1.

The goal is to keep the table-first Backoffice experience compact and avoid wasting vertical space with embedded forms, large paddings or oversized visual blocks.

## Included views

- `/admin/master-data/brands`
- `/admin/master-data/device-models`
- `/admin/master-data/categories`

## UX changes

- Create and edit actions now open compact modals.
- Activate / deactivate and delete actions now use compact confirmation modals.
- The main table area stays visible and uncluttered.
- The demo persistence note is smaller and less visually dominant.
- Action buttons, modal controls, notices and modal spacing use tighter paddings and smaller text.

## Persistence boundary

QA status: PASS — CI, Automated QA, Browser QA, export smoke and deploy smoke must pass on the final PR HEAD before merge approval is requested.

The CRUD behavior remains demo-only and in memory.

This PR does not add backend, database, localStorage or fake persistence.

## Browser QA

Browser QA now validates for brands, device models and categories:

- route deep link;
- table render;
- create action opens a modal;
- edit action opens a modal;
- deactivate action uses a confirmation modal;
- delete action uses a confirmation modal;
- create / edit / deactivate / delete behavior;
- search and reset;
- desktop screenshot;
- mobile screenshot;
- no horizontal overflow.

## Explicitly not included

This PR does not migrate Inventory Intake yet.

This PR does not change Ecommerce.

This PR does not change Storefront.

This PR does not add real persistence.
